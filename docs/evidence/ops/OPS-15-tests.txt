OPS-15 — log knex "Connection ended unexpectedly" ใน integration ของ CI (spec 07 AC-26, review #122)

== สาเหตุจริง
medusaIntegrationTestRunner (@medusajs/test-utils 2.22.1) snapshot/restore DB จาก template ใน beforeEach
ของทุก test: restorePostgresDatabaseFromTemplate → pg_terminate_backend ทุก backend ของ DB ของ test
แล้ว DROP/CREATE DATABASE ใหม่ connection ที่ว่างอยู่ใน pool ของ app (knex PG_CONNECTION ที่ module ทุกตัวใช้ร่วมกัน)
จึงถูกปิดฝั่ง server — pg client ยิง 'end' → knex ติดป้าย __knex__disposed = "Connection ended unexpectedly"
แล้วเตือน "Connection Error: ..." ทุกครั้งที่ pool หยิบ connection ที่ตายนั้นขึ้นมา validate ใน query ถัดไป

== วิธีแก้ (ที่ต้นเหตุ ไม่กรอง log)
integration-tests/setup-after-env.ts (setupFilesAfterEnv ของ integration:http): beforeEach ระดับบนสุดรันก่อน
beforeEach ของ runner → releaseIdlePgConnections(): knex.destroy() (รอ connection ที่ใช้อยู่คืน) แล้ว
knex.initialize() pool ใหม่บน instance เดิม — ไม่มี connection เหลือใน pool ตอน DB ถูก terminate
รอบแก้ตาม review (REQUEST CHANGES #156): ก่อน destroy() รอจน pool ว่าง (numUsed/numPendingAcquires/
numPendingCreates = 0) ต่อเนื่อง 50ms (timeout 5s → ไม่ destroy) เพราะ subscriber เบื้องหลัง (search ingestion
ของ product.created) ยังใช้ pool อยู่หลัง test จบ และ tarn Pool.destroy() abort acquire ที่รออยู่ของมัน
