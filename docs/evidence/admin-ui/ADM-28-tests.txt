## 5. ข้อสรุปสาเหตุ
- ไม่ใช่ H1a (request ไม่ช้า/ไม่ล้ม และ list = ผลของ q จริง), ไม่ใช่ H1b (option เป้าหมายไม่เคยมี), ไม่ใช่ H2 (รายการเปิดและมี request q)
- **H3 (ข้อมูลเกินจากการค้นหา) แบบที่ spec ไม่ได้คาด — ต้นเหตุอยู่ใน test (ข้อมูลทดสอบ)**:
  `q` ของ Medusa 2.22.1 (`@medusajs/utils/dist/dal/mikro-orm/mikro-orm-free-text-search-filter.js:74–110`) แยกคำด้วย `/\s+/`
  แล้ว AND `$or: [{field: {$ilike: "%คำ%"}}]` ทีละคำ — คำค้น "<tag> col 249" จึงเป็น 3 คำ; tag ของ test คือ `adm9${Date.now()}`
  และทั้งสอง run ที่ล้ม tag มี "249" อยู่ในตัวเลข (17949142**49**944, 1794592**249**544) → คำ "249" ตรงทุก 250 รายการ (ใน title และ handle)
  → server ตอบ count=250 เรียงตาม id แบบ string (pcol_<tag>_0, _1, _10, _100 …) col 249 ไม่อยู่ใน 10 รายการแรก
  และ test ไม่ scroll ให้โหลดหน้าถัดไป → click รอจน timeout ของ test 120s (playwright.config ไม่ตั้ง actionTimeout)
- โอกาสเกิด ≈ 1% ต่อ run (เลข 13 หลักมี "249" ติดกัน) สอดคล้องกับที่ล้ม 2 ครั้งในหลายสิบ run
- ไม่ใช่ปัญหาใน `program-form.tsx` หรือใน `@medusajs/dashboard` (Combobox/useComboboxData ทำงานถูกต้องตามผลที่ได้) — ไม่แตะ src/admin/
